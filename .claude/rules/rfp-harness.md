## 0. 이 문서의 적용 범위

**이 리포(`ats.minahdev.cloud`)는 Jekyll 개발 보고서 사이트다. 애플리케이션 코드는 여기 없다.**

- 이 하네스는 **애플리케이션 코드를 만들 때** 적용한다. 보고서 페이지(`.md`, `_config.yml`)를
  고칠 때는 적용 대상이 아니다 — 그건 `CLAUDE.md`를 따른다.
- 아래 `[Task 1]`을 이 리포에서 그대로 실행하면 보고서 사이트 안에 모노레포가 생긴다.
  **애플리케이션은 별도 리포에 만들고, 이 문서를 거기로 복사해 쓴다.**
- 보고서 본문(요구사항 분석·시스템 설계 장)을 쓸 때는 아래 요구 ID를 인용해 일관성을 맞춘다.

## 1. AI 행동 규칙 (Rule Set)

1. **[명확성]** 모호한 표현 금지. 수치와 조건으로 쓴다.
   - ✗ "검색이 빨라야 한다" → ✓ "지원자 10만 건 기준 다중 조건 검색 p95 300ms 이내"
   - ✗ "이력서를 잘 파싱한다" → ✓ "인적사항·학력·경력·스킬 4개 필드 추출 정확도 95% 이상"
2. **[원자성]** 복합 기능을 한 덩어리로 만들지 않는다. 요구 ID 하나 = 독립 검증 가능한 모듈 하나.
3. **[추적성]** 생성하는 모든 소스·테스트·설정 파일 최상단에 요구 ID를 주석으로 남긴다.
   ```python
   # Requirement ID: SFR-001
   # 이력서 원문에서 구조화 필드를 추출한다.
   ```
   ```tsx
   // Requirement ID: SFR-005
   ```
4. **[검증성]** 요구사항 코드를 만들면 그 검수 기준을 확인하는 테스트를 **같은 작업에서** 만든다.
   테스트 없는 구현은 완료가 아니다.
5. **[개인정보]** 이력서는 민감 개인정보다. 실제 인적사항을 테스트 픽스처·시드 데이터·로그·
   커밋 메시지에 넣지 않는다. 항상 합성 데이터를 쓴다 (DAT-001).

## 2. 시스템 아키텍처 및 5인 R&R

```
[ Frontend: Vercel ]                    [ Backend: AWS ]

React + TypeScript  ──── /api ────▶  FastAPI (Docker / EC2)
├── 지원자 목록·상세                   ├── 공고·지원자 CRUD, 전형 단계 전환
├── 공고 관리                          ├── 검색·필터 API
├── 로그인 / 권한                      ├── 이력서 파싱 · 자동 스크리닝
└── 채용 현황 대시보드                  └── 매칭 추천

                                     [ 데이터 · 스토리지 ]
                                     ├── PostgreSQL (RDS)  지원자·공고·전형
                                     ├── S3                이력서 원본
                                     └── SQS → SES         면접 알림 메일
```

### R&R 및 모듈 소유권

| 담당 | 영역 | 디렉토리 | 스택 | 담당 요구 ID |
| :--- | :--- | :--- | :--- | :--- |
| **재우 A** | 백엔드 · 총괄 | `services/api/` | FastAPI, PostgreSQL | SFR-002, SFR-003, SFR-004, SEC-001, QUA-002 |
| **우정 B** | 검색 · 데이터 | `services/search/` | PostgreSQL, SQL | SFR-005, PER-001, DAT-001 |
| **민아 C** | 파일 · 알림 | `services/files/`, `services/notify/` | S3, SES, SQS | SFR-001, SFR-006, INT-001 |
| **소연 D** | 프론트엔드 | `apps/web/` | React, TypeScript, Vercel | SFR-007, INT-002 |
| **수택 E** | 인프라 · 품질 | `infra/`, `tests/`, `.github/` | Docker, Actions, EC2 | QUA-001, QUA-002, SEC-002, PER-002 |

QUA-002(공정성)는 **재우 A가 구현에서 피처를 배제**하고 **수택 E가 검증에서 확인**하는 이중 책임이다.
한쪽만 수행한 상태로 완료 처리하지 않는다.

모듈 경계를 넘는 변경은 소유자 리뷰를 거친다. 소유자가 아닌 디렉토리를 임의로 리팩터링하지 않는다.

## 3. 상세 요구사항 명세표

### 3.1 기능 영역 (SFR)

| 요구 ID | 분류 | 정의 및 세부 내용 | 코드 위치 | 검수 기준 |
| :--- | :--- | :--- | :--- | :--- |
| **SFR-001** | 파싱 | PDF / DOCX 이력서에서 인적사항 · 학력 · 경력 · 스킬 구조화 추출 | `services/files/parser.py` | 4개 필드 추출 정확도 **95% 이상** (합성 테스트셋 200건 기준) |
| **SFR-002** | 스크리닝 | 공고 자격요건 대비 지원자 자동 스코어링 및 부적격 필터링 | `services/api/screening.py` | 필수요건 미충족 지원자 **100% 식별**, 오탐 5% 이하 |
| **SFR-003** | 추천 | 지원자–공고 매칭 추천 (스킬 임베딩 유사도 + 규칙 가중) | `services/api/matching.py` | 상위 5건 기준 **Recall@5 90% 이상** |
| **SFR-004** | 전형 관리 | 서류 → 면접 → 최종 전형 단계 전환 상태 머신 | `services/api/pipeline.py` | 정의되지 않은 상태 전이 **100% 차단**, 전이 이력 전건 기록 |
| **SFR-005** | 검색 | 지원자 다중 조건 검색 · 필터 (경력 · 스킬 · 전형 상태 · 기간) | `services/search/query.py` | 10만 건 기준 조건 조합 20종 **전건 정확 반환** |
| **SFR-006** | 알림 | 면접 일정 등록 시 지원자 · 면접관 메일 발송 (SQS 큐 → SES) | `services/notify/` | 발송 실패 시 **3회 재시도 후 DLQ 이동**, 중복 발송 0건 |
| **SFR-007** | 대시보드 | 공고별 지원 현황 · 전형 단계별 인원 · 기간별 추이 통계 | `apps/web/dashboard/` | 집계 결과가 DB 원본 쿼리와 **전건 일치** |

### 3.2 인터페이스 영역 (INT)

| 요구 ID | 분류 | 정의 및 세부 내용 | 코드 위치 | 검수 기준 |
| :--- | :--- | :--- | :--- | :--- |
| **INT-001** | 업로드 | presigned URL 기반 이력서 S3 직접 업로드 (서버 경유 금지) | `services/files/upload.py` | 20MB 파일 업로드 성공, 허용 외 확장자 **차단** |
| **INT-002** | 반응형 | 지원자 목록 · 상세 · 공고 관리 화면 모바일 대응 | `apps/web/` | 375px 폭에서 가로 스크롤 **0**, 주요 동작 전부 수행 가능 |

### 3.3 성능 · 보안 · 데이터 · 품질 영역 (PER / SEC / DAT / QUA)

| 요구 ID | 분류 | 정의 및 세부 내용 | 코드 위치 | 검수 기준 |
| :--- | :--- | :--- | :--- | :--- |
| **PER-001** | 성능 | 지원자 검색 응답 속도 — 인덱스 튜닝 포함 | `services/search/` | 10만 건 기준 **p95 300ms 이내** (부하 테스트 측정) |
| **PER-002** | 성능 | 이력서 업로드 비동기 처리 — 파싱을 요청 경로에서 분리 | `services/files/` | 업로드 API 응답 **1초 이내**, 파싱은 큐에서 처리 |
| **SEC-001** | 인증 · 인가 | JWT 인증 및 역할 기반 접근 제어 (채용담당자 / 면접관 / 관리자) | `services/api/middleware/` | 미인증 **401**, 권한 없음 **403**, 타 공고 지원자 조회 차단 |
| **SEC-002** | 개인정보 | 이력서 저장 암호화(S3 SSE), 전송 TLS, 접근 로그 기록, 보관기간 만료 파기 | `infra/`, `services/files/` | 평문 저장 **0건**, 조회 이력 전건 로깅, 만료 건 자동 파기 |
| **DAT-001** | 데이터 | 성능 검증용 지원자 더미 데이터 10만 건 생성 | `services/search/seed.py` | 실제 개인정보 **0건**(전량 합성), 분포가 실사용 가정과 유사 |
| **QUA-001** | 테스트 | 요구 ID별 PyTest / Vitest 자동화 테스트 | `tests/` | 핵심 로직 커버리지 **80% 이상**, CI에서 자동 실행 |
| **QUA-002** | 공정성 | 채용 판단에서 차별금지 속성 배제 — 성별 · 연령 · 출신지역 · 출신학교 | `services/api/screening.py`, `matching.py` | 해당 속성이 스코어링 피처에 **미포함**, 편향성 점검 리포트 제출 |

> **QUA-002는 형식 요건이 아니다.** 채용 자동화는 차별 판단이 그대로 사람의 불이익으로
> 이어진다. 스코어링·추천 피처를 추가할 때마다 이 항목을 확인하고, 대리 변수(예: 졸업연도 →
> 연령, 거주지 → 출신지역)도 함께 배제한다.

## 4. 태스크 프롬프트 (Execution Directives)

### [Task 1] 모노레포 뼈대 구축

```
RFP 하네스에 따라 Vercel + AWS 아키텍처용 모노레포 뼈대를 구축해줘.
1. 루트에 pnpm workspace 설정 (apps/web, services/api, services/search, services/files, services/notify)
2. apps/web: React + TypeScript + Vite, /api → http://localhost:8000 로컬 프록시
3. services/api: FastAPI 기본 앱, CORS 미들웨어 및 JWT 검증 골격 (SEC-001)
4. .env.example에 RDS · S3 · SES/SQS 접속 키를 빠짐없이 정의 (실제 값 금지)
5. 생성하는 모든 파일 상단에 관련 요구 ID 주석 명시
```

### [Task 2] SFR-001 이력서 파싱 모듈

```
SFR-001에 따라 services/files/parser.py에 이력서 구조화 파서를 구현해줘.
- PDF / DOCX 입력에서 인적사항 · 학력 · 경력 · 스킬 4개 필드 추출
- 추출 실패 필드는 None으로 두고 예외를 삼키지 말 것
- 합성 이력서 픽스처 기반 정확도 측정 테스트(tests/test_parser.py) 동반 생성
- 픽스처에 실제 인적사항 사용 금지 (DAT-001)
```

### [Task 3] SFR-005 / PER-001 검색 API

```
SFR-005와 PER-001에 따라 services/search/query.py에 지원자 검색을 구현해줘.
- 경력 연차 · 스킬 · 전형 상태 · 지원 기간 다중 조건 조합
- 조건별 인덱스 설계를 주석으로 근거와 함께 남길 것
- 10만 건 시드 기준 p95 300ms를 측정하는 성능 테스트 동반 생성
```

### [Task 4] SFR-003 / QUA-002 매칭 추천

```
SFR-003에 따라 services/api/matching.py에 지원자–공고 매칭 추천을 구현해줘.
- 스킬 임베딩 유사도 + 자격요건 규칙 가중 결합
- QUA-002 준수: 성별 · 연령 · 출신지역 · 출신학교 및 그 대리 변수를 피처에서 배제하고,
  배제 목록을 코드 상수로 명시할 것
- Recall@5 측정 테스트와 피처 목록 검증 테스트를 함께 생성
```

## 5. 검증 체크리스트

구현 완료 후 스스로 수행한다. 통과하지 못한 항목은 완료로 보고하지 않는다.

- [ ] **[추적성]** 생성된 모든 소스·테스트 파일 상단에 `Requirement ID: XXX-000` 주석이 있는가
- [ ] **[검증성]** `pytest tests/` 실행 시 각 요구 ID의 검수 기준 통과 여부가 출력되는가
- [ ] **[커버리지]** 핵심 로직 커버리지가 80% 이상인가 (QUA-001)
- [ ] **[보안]** 미인증 401 · 권한 없음 403이 실제로 차단되는가 (SEC-001)
- [ ] **[개인정보]** 시드·픽스처·로그에 실제 인적사항이 0건인가 (DAT-001, SEC-002)
- [ ] **[공정성]** 스코어링·추천 피처에 차별금지 속성과 그 대리 변수가 없는가 (QUA-002)
- [ ] **[설정]** `.env.example`에 RDS · S3 · SES/SQS 키가 빠짐없이 정의되고, **실제 값은 하나도
      들어 있지 않은가** — 이 리포는 public이다
- [ ] **[프록시]** 로컬 프론트(3000) → 백엔드(8000) 호출이 CORS 차단 없이 동작하는가

### 검증 명령

```bash
pytest tests/ --cov=services --cov-report=term-missing   # QUA-001
grep -rL "Requirement ID:" services/ apps/ --include='*.py' --include='*.ts*'  # 추적성 누락 파일
```
